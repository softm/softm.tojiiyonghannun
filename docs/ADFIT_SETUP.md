# 토지이용한눈 · 공통 카카오 AdFit 운영 가이드

적용일: 2026-11-13
운영 주소: https://tojiiyonghannun.designboard.net/
공통 기준: https://github.com/softm/softm.github.io/blob/main/ADFIT-COMMON-ADS.md

## 광고 지면

| 지면 | 광고 단위 | 규격 | 노출 시점 |
|---|---|---|---|
| 검색 결과 인피드 | DAN-4nmORIg1At492nrf | 320×100 | 검색 결과가 7개 이상일 때 6번째 결과 뒤 |
| 필지 상세 결과 | DAN-71yamqyQ7AV0rxk2 | 320×100 | 선택 필지의 상세 결과 표시 후 |

광고 단위 ID는 토지이용한눈에 기존 등록된 값입니다. 실제 광고 매체 승인과 송출 성공은 AdFit 관리자 화면과 운영 사이트에서 별도로 확인해야 합니다. 다른 사이트의 광고 단위를 재사용하지 않습니다.

## 구현 기준

1. 검색 결과 인피드는 같은 ID가 6·12·18번째마다 중복 노출되던 구조를 6번째 결과 뒤 1회로 수정합니다.
2. adfit-config.js는 사이트 전용 도메인과 ID·규격을 갖습니다. adfit.js는 SDK를 페이지당 한 번만 로드하고 각 지면은 한 번만 광고를 요청합니다.
3. IntersectionObserver의 200px 여유 범위에서 광고를 지연 요청합니다. 검색 재실행·상세 패널 재진입·숨김과 표시로 자동 새로고침하지 않습니다.
4. PC와 모바일 모두 현재 확보된 320×100 광고 단위를 사용합니다. 실제 가용 폭이 320px 미만이면 축소하거나 잘라내지 않고 비노출합니다.
5. 도메인이 다르거나 Android WebView가 AdMobNative/1을 표시하면 광고 요청과 컨테이너를 차단합니다. SDK 오류, NOAD, 30초 응답 없음 시 빈 공간을 제거합니다.
6. 광고 라벨을 표시하고 필지 선택·조회·지도 이동·계정 입력 등 조작과 겹치지 않게 배치합니다. 검색어, PNU, 계정 정보는 광고 렌더 함수로 전달하지 않습니다.
7. PC 728×90, 하단 접이식, 첫 방문 광고는 전용 단위 발급 전 비활성입니다. 기존 DAN ID를 복제하지 않습니다.
8. 개인정보처리방침과 앱의 Android 광고 신고는 실제 광고 제공 방식을 기준으로 업데이트합니다.

## 변경 파일

- adfit-config.js: 고유한 사이트 전용 광고 단위 2개
- adfit.js: SDK·지연 요청·NOAD·중복·화면 크기·네이티브 광고 차단
- index.html, app.js: 중복 검색 슬롯 제거 및 에셋 버전 변경
- styles.css: 모바일에서 광고 크기 임의 축소·잘림 방지
- tests/adfit.test.mjs, tests/adfit-runtime.test.mjs: 설정 및 시뮬레이션 회귀 검증
- privacy.html: 광고·계정 처리 안내 최신화

## 배포 후 수동 점검

1. GitHub Pages 빌드·테스트·배포 성공.
2. 실제 사이트에서 7개 이상의 검색 결과가 있을 때 6번째 뒤 광고 요청과 라벨 확인.
3. 6개 이하, 320px 미만, 광고 차단기·광고 미수신 시 빈 공간 없음.
4. 상세를 열면 해당 필지 상세 단위만 호출되는지 확인.
5. 화면 상태를 바꾸거나 검색을 다시 해도 동일 지면의 자체 새 광고 요청이 없는지 확인.
6. Android 네이티브 광고 사용 WebView에서 AdFit 네트워크 요청 0건.
7. Kakao AdFit 관리 콘솔에서 실제 승인과 송출 상태 확인.
